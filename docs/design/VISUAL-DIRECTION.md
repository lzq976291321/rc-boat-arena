# 画面制作分工与湿地版本方向

记录日期：2026-09-21。根据项目讨论，由用户确认沉淀。

## 模型与 Three.js 的分工

模型提供物体形状、表面贴图和材质参数，也可能包含骨骼与动画。Three.js 负责场景装配、实时光照、环境反射、阴影、运动、镜头与后处理。两者并非互斥：程序生成的几何体也是模型，模型自带动画也要由运行时播放。

- 船、树、木屋等资产优先看轮廓、比例、材质资料与可用许可。
- 水常用简单网格配合反射渲染、细小波纹、Fresnel、深浅色与尾流。
- 雾、天空、曝光与镜头决定空间层次。同一个模型在不同环境下会呈现完全不同的质感。
- GLTFLoader 表示加载外部资产；Geometry 构造表示程序几何；ShaderMaterial 表示可编程表面；资产来源最终以模型文件和源码为准。

## 画面方向

先设计一张好看的画面，再让它动起来。近景轮廓框住画面，中景形成水道，远景融入雾。天空与岸景共同决定水面倒影的质量；波纹要足够克制，保留反射结构。统一冷暖与明暗，低机位展示水面，驾驶镜头保持可读性。

参考：Chetan Ankola 的 [Stillwater 演示](https://x.com/chetanankola/status/2101595285675970853)。作者确认使用 Three.js，公开产品介绍包含 Blender 源模型、反射水面、尾浪和多种光照。具体反射与雾算法未公开；本项目独立实现同类视觉方向，不声称使用作者源码。

## 本次实现约定

- 新增 `/swamp/` 独立入口，保留原有竞速体验。
- 外部模型必须有明确、允许使用修改和再分发的许可。
- 页面“素材来源”、`public/assets/swamp/SOURCES.md` 和机器可读 manifest 标注名称、作者、原始链接、许可和本项目改动。
- 程序生成的天空、水、雾、尾浪等与下载模型分别标注。
- 以浏览器实际画面、加载、驾驶方向、暂停和移动布局验收；不把录屏或一次构建成功当作完整验收。
